# Food Desert AI

> Type a US place and see whether its 2020 census tract meets USDA's low-income and low-access test (the measure often called a food desert), the counts behind the answer, and what new supermarkets would change. It is an estimate computed live with USDA ERS's rule, not an official USDA designation.

A React app built for the [Congressional App Challenge](https://www.congressionalappchallenge.us/). It computes USDA ERS's low-income & low-access test on 2020 Census blocks and USDA's list of SNAP-authorized supermarkets, shows both published USDA maps beside the estimate, recomputes the test when you place stores, suggests where supermarkets would change the result, and turns the tract's numbers into a rules-based action plan. Every number comes from deterministic code over public data; nothing at runtime is generated by AI.

Docs: the method contract is [`docs/07-access-test-redesign.md`](docs/07-access-test-redesign.md), Suggest sites and the action plan are [`docs/08-suggest-sites-and-plan.md`](docs/08-suggest-sites-and-plan.md), the datasets are [`docs/data.md`](docs/data.md), and [`docs/README.md`](docs/README.md) indexes the rest. The CAC submission packet is [`docs/CAC_SUBMISSION.md`](docs/CAC_SUBMISSION.md).

## What it answers, and for whom

For any US point: does the census tract there meet USDA ERS's low-income and low-access test, what are the counts and reasons behind the answer, and what would one or more new supermarkets change?

- City planners and public-health teams weighing a grocery intervention
- Students, educators and community advocates learning how food access is measured
- Congressional App Challenge judges

## How it decides

USDA rates census tracts, not cities, so the unit is the **2020 census tract** containing the searched point. Any point in the same tract gives the same result.

1. **Tract:** Census TIGERweb (Census 2020, layer 6) at the point.
2. **Residents:** every populated 2020 Census block in the tract (POP100 > 0), from a committed county file (Santa Clara and Alameda CA, Washington MS, Apache AZ) or live from TIGERweb. The block populations must add up to the tract's 2020 population, or the answer is Unknown.
3. **Stores:** USDA SNAP-authorized retailers labelled "Supermarket" or "Super Store" (a dated snapshot of the SNAP Retailer Locator in `public/data/stores/`), minus hand-reviewed exclusions: warehouse clubs, military commissaries and exchanges, fuel stations (`scripts/store-exclusions.json`). The same file moves a store whose SNAP coordinate is provably wrong to its real location (one so far, in Chinle AZ; see [`docs/data.md`](docs/data.md)).
4. **Distance:** straight-line (haversine) miles from each block's internal point to the nearest counted store.
5. **Distance limit T:** 1 mile if USDA ERS 2025 flags the tract urban, 10 miles if rural. Without an ERS 2025 row, the urban/rural code of the majority of block residents decides, and the app says so.
6. **Low access:** at least 33% of the tract's residents, or at least 500 of them, live more than T from a counted store (a block at exactly T is within).
7. **Low income:** USDA ERS 2025 `LowIncomeTracts`, as published (ERS's 2025 Food Access Research Atlas).
8. **Result**, a three-valued AND: **MEETS TEST** only when both hold; a known "no" on either gives **DOES NOT MEET** even if the other input is missing; otherwise **UNKNOWN** with a named reason. The app never guesses.

A point outside every US census tract gets no result at all: the search reports "No census tract found. Try a different US location."

| Unknown reason | When |
|---|---|
| `tract_unavailable` | the point → tract lookup failed (network) |
| `no_residents` | the tract has no residents (USDA doesn't rate those) |
| `blocks_unavailable` / `blocks_incomplete` | the blocks didn't load, or their populations don't add up to the tract's |
| `stores_unavailable` | a store tile the tract needs failed to load |
| `stores_not_covered` | Puerto Rico, American Samoa or the Northern Mariana Islands, which run nutrition block grants instead of SNAP, so the SNAP list has no stores there |
| `ers_unavailable` | the ERS county file didn't load (urban/rural and income unknown; "Try again") |
| `income_unavailable` | no ERS 2025 row (the result can still be DOES NOT MEET when the tract isn't low access) |
| `urban_unavailable` | no ERS urban flag and no urban/rural majority among the blocks |

Each result shows an evaluation trace, distance bands (the residents beyond T split into up to 1.1 T, up to 1.5 T and farther) and a borderline flag when the low-access answer would change between 0.9 T and 1.1 T.

## Scope: Point, Tract, City

- **Tract** (the verdict): header, MEETS TEST / DOES NOT MEET / UNKNOWN, the tract and its residents, the sentence behind the answer, bands, trace.
- **Point:** one line, the straight-line distance from the exact spot to its nearest counted supermarket. No verdict: one spot doesn't decide USDA's test, the tract's residents do.
- **City:** a city search shows the tract at the searched point and says "USDA rates census tracts, not cities." **Summarize {city}** adds up the tract test for the residents inside the Census place boundary: a block counts when its internal point lies inside the full-resolution place polygon, and the in-city blocks must add up to the place's 2020 population exactly, or the summary is Unknown. Tracts on the city line are tested on all their residents; totals count in-city residents only. It reports residents beyond their own tract's limit, residents in tracts meeting the test, residents in tracts flagged on the 2019 and 2025 USDA maps, and a sortable tract table that opens each tract. A city never gets a pill.

## The two USDA reference maps

Every estimate shows both maps USDA ERS publishes (they can disagree with each other and with the estimate):

- **2019 supermarket map (LRAM):** 2010 tract boundaries, matched to the 2020 tract by identical GEOID only, with its published low-access share.
- **2025 SNAP-store map (SRAM):** counts SNAP-authorized stores of every size, including convenience and dollar stores (not farmers markets).

When either map's flag disagrees with the estimate, the app names the input that differs (the income flag, 2019 stores and 2010 population, or SRAM counting smaller stores).

## Placing stores

Pins carry a format. Only supermarkets count, because USDA's measure is supermarket-based:

| Format | Counts? | Shown as |
|---|---|---|
| Supermarket or supercenter | yes | — |
| Small grocery or corner store | no | "USDA's supermarket-based measure doesn't count small grocers." |
| Dollar store | no | "USDA's supermarket-based measure excludes dollar stores." |
| Farmers or mobile market | no | "Neither USDA map counts farmers or mobile markets." |

The scenario reruns the same rule on the same blocks with each block's distance the smaller of its baseline and its nearest supermarket pin (up to 10 pins). It reports residents beyond T, residents brought within T, the test result, the gap still to close while the tract stays low access, residents within ½ mile (urban tracts only), and an estimate of no-vehicle households beyond ½ mile (ERS `TractHUNV` apportioned by housing units; hidden under 20). These are labelled "computed": duplicate and far-away pins change nothing by construction, and there are no jobs, dollar or health projections.

A collapsed **context box** says what studies found instead of projecting: grocery establishment size (BLS QCEW 2025) and net retail employment after Walmart openings (Neumark, Zhang & Ciccarella 2008); new-supermarket studies in Philadelphia (Cummins et al. 2014), Pittsburgh (Dubowitz et al. 2015; Richardson et al. 2017) and the Bronx (Elbel et al. 2015). It ends "This app does not project health outcomes."

## Suggest sites and the action plan

Both are deterministic code; no model runs at runtime.

- **Suggest sites** (offered when the tract is low access) runs a greedy search for up to 3 points that bring the most residents newly within T, building on any supermarkets you've placed, and stops as soon as the tract is no longer low access. In the four bundled counties the candidates are existing commercial sites from OpenStreetMap (vacant shops, retail and commercial buildings of 10,000 sq ft or more, retail areas of 2 acres or more; never operating supermarkets or businesses in use); elsewhere, or when no commercial site helps, they are points inside populated Census blocks, and the list says why. When the commercial picks leave the tract low access, the list offers Census block points instead (Greenville's one gaining commercial site, for example, leaves it meeting the test). Each pick shows "+≈N residents within T" and the result after it. **Add as store** turns a pick into a supermarket pin (which then joins share links); suggestions never enter the URL until added. Every list carries: "Distance only. Ignores land, zoning, cost, and whether a grocer would open there. Commercial sites are existing OpenStreetMap features; the app doesn't know whether they're available."
- **Action plan · rules applied to this tract's numbers** renders under the references when the verdict is known: at most 6 items from fixed rules (site a full-line grocer near the suggested sites when they flip the result; SNAP and WIC authorization; covering distance with SNAP online purchasing, transit or a mobile market; GusNIP incentives; healthy-food financing; the not-low-income and not-low-access cases). Each `why` quotes only this tract's computed numbers, each link was verified against the official page (`VERIFIED_SOURCES` in `src/engine/actionPlan.js`), and the card ends "Not advice from USDA; check each program's current eligibility."

## Other features

- **Share links** replay the location and the placed stores with their formats (`#…&pins=lat,lng;…&pt=s;g;…` in the URL hash; no database).
- **Community profile:** Census ACS 5-year (population, poverty rate, median household income) and CDC PLACES (diabetes, obesity). It never decides the verdict and fails on its own.
- **US map mode:** USDA's 2019 atlas (LRAM) low-income & low-access flags aggregated by state.
- **Phone layout:** information only, no map; Suggest sites works as a list.
- **Installable PWA:** offline app shell; data calls stay network-only, so stale data is never shown as fresh.

## Limitations

1. **An estimate, not an official designation.** It applies ERS's rule to newer inputs; ERS's published maps stay the record and are shown beside it.
2. **Block internal points:** each block's residents are placed at the block's internal point.
3. **Straight-line distance,** not road distance or travel time.
4. **Census privacy noise:** 2020 block populations include the Census Bureau's disclosure-avoidance noise; the app rounds counts (exact below 100, to about the nearest 10 above, with "≈").
5. **The SNAP list misses supermarkets that don't take SNAP,** and it follows SNAP's own store-type labels.
6. **Territories without SNAP** (Puerto Rico, American Samoa, Northern Mariana Islands) are never measured (`stores_not_covered`).
7. **Connecticut community profile:** ACS 2022 uses Connecticut's new planning-region county codes, so `/api/acs` fails for 2020 Connecticut tract ids and those profile rows show "unavailable". The verdict is unaffected.
8. **Very large City summaries are untested:** measured up to Sacramento (524,943 residents, 147 tracts, live); Los Angeles- or New York-size places haven't been tried.
9. Commercial site candidates exist only for the four bundled counties; Suggest sites uses Census block points everywhere else.

## Quick start

Prerequisites: Node.js 20.19+ or 22.12+ (Vite 8's requirement) and npm.

```bash
npm install
cp .env.example .env      # optional: add CENSUS_KEY for the ACS profile rows
npm run dev -- --host 127.0.0.1 --port 5173
```

`npm run dev` starts Vite. `vite-plugin-api-dev.js` runs the real `api/acs.js` handler at `/api/acs` (in `vite` and `vite preview`), and the Vite dev proxy forwards `/api/census-geocoder`, `/api/nominatim` and `/api/cdc` upstream (production limits these to exact paths in `vercel.json`).

| Variable | Required? | Used by |
|---|---|---|
| `CENSUS_KEY` | No | Census ACS rows in the community profile, read server-side only by `api/acs.js` (Vercel) and by the local dev middleware. Never prefix it with `VITE_`: Vite inlines `VITE_*` values into the client bundle. |
| `VITE_CARTO_KEY` | No | Optional override for the US map's CARTO raster tile key; the built-in key is public by design. |

Without any key, everything works except the ACS rows of the community profile, which show "unavailable". The tract test does not use ACS.

The `@` import alias maps to `src/` (`vite.config.js`).

## Deployment

Vercel (Vite preset): `npm run build` builds `dist/` and runs the key check; `api/acs.js` deploys as a serverless function; set `CENSUS_KEY` (no `VITE_` prefix) in the Vercel project settings. `vercel.json` holds only pass-through rewrites, limited to the exact upstream paths the app calls and carrying no keys:

| Source | Destination |
|---|---|
| `/api/census-geocoder/geocoder/:path(geographies/coordinates\|locations/onelineaddress)` | `https://geocoding.geo.census.gov/geocoder/:path` |
| `/api/nominatim/:path(search\|reverse)` | `https://nominatim.openstreetmap.org/:path` |
| `/api/cdc/resource/:path(cwsq-ngmh\.json)` | `https://data.cdc.gov/resource/:path` |

Census TIGERweb is called directly from the browser (keyless, CORS). Everything else the test needs is a static file under `public/data/`.

## Security notes

- **No keys in the client.** `CENSUS_KEY` is read only by `api/acs.js` and the local dev middleware. Client code may read only public `VITE_*` variables (`tests/keyHygiene.test.js`).
- **The build key check.** `npm run build` ends with `scripts/check-bundle-for-keys.mjs`, which fails if the value of any private env variable (plain or URL-encoded) or a known key shape appears in `dist/`, and prints the variable name and length, never the value (`tests/bundleGuard.test.js`).
- **No open relays.** `api/acs.js` accepts only `GET ?fips=<11-digit tract>`, asks Census for a fixed variable list and never echoes the upstream URL. The `vercel.json` rewrites match exact paths.
- **Third-party text is escaped** (SNAP store names, OpenStreetMap vacant-shop names) before Leaflet writes it as HTML.
- Known gap: `/api/acs` has no rate limit yet.
